## The project — SnapClaim

**Point a phone at damage, speak one line — get a claim-ready report where every number is measured, cited, and checked by an independent model.**

- 📷 photo + 🎙 voice note → **SAM 3.1** masks the damage (crack / stain / peel / dent)
- 📐 **deterministic math** measures area % and calibrated lengths — no LLM in the measurement
- 🧠 **Muse Spark 1.3** writes the annexure; every sentence must cite a measured number or the build fails
- 🔍 **Spark Open** (Meta open weights) re-measures independently — disputes print in red, never hidden
- 📄 code-drawn SVG/PDF: masks over the photo, receipts table, fully replayable — **computed, not generated**

Repo (public): **[github.com/Parithosh-Varma/snapclaim](https://github.com/Parithosh-Varma/snapclaim)** · implementation plan PDF in `docs/`

## Why this can place

- **Measured, not generated:** every number is computed from the pixels and replayable from a receipts file — a judge can verify a report live.
- **Felt problem:** deposit disputes, small claims, monsoon damage — documentation people need and can't get.
- **Meta stack depth:** SAM 3.1 + Muse Spark + Spark Open + Muse Voice Transcribe — four models with visibly distinct jobs.
- **Bonus coverage:** open-weights prize (Spark Open skeptic), agentic workflow, viral clip potential.
